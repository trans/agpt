## 15:26 - Context Alpha Gate

Implemented a context-conditioned residual gate:

```text
alpha(c) = alpha_max * sigmoid(phi . features(c))
logits   = log q_tree(c) + alpha(c) * residual_logits(c)
```

The default `alpha_max` is `2 * prior_residual_scale`, and the gate weights are
zero-initialized. With `prior_residual_scale=0.10`, the initial alpha is exactly
`0.10`, matching the previous fixed-alpha setup.

Fair carved split partial run:

```text
run: carved_context_alpha_scale010_l2_002_d64_e3
prior only: 3.859, mean alpha 0.100
epoch 1:    3.811, mean alpha 0.148
epoch 2:    3.820, mean alpha 0.148
```

The epoch-1 result is a slight new best over fixed alpha. More importantly,
epoch 2 is much more stable than the fixed-alpha `L2=0.02` run, which drifted
to `3.868`.

Scaling note: the first context-alpha run had to build a feature-row cache. That
took about `242s`, raised peak RSS to about `6GB`, and produced a `324MB` cache
for the 1M-character carved split. Future runs can reuse that cache, but
Gutenberg-scale runs need a faster and more compact prior/feature path.

## 2026-06-14 - Depth-By-Depth NumPy Prior Compiler

Added a vectorized count-prior compiler in
`agpt_ultra/vectorized_count_prior.py`.

Shape of the algorithm:

```text
1. Build packed count tables.
2. Precompute node features depth by depth.
3. Maintain dense Witten-Bell distributions only for the previous depth.
4. Generate prior rows in chunks:
   q_0 = unigram
   for d in 1..D:
       lookup depth-d context keys in bulk
       w_d = sigmoid(theta . features_d)
       q_d = (1 - w_d) q_{d-1} + w_d MLE_d
```

The compiler writes both prior log-prob rows and deepest-context feature rows.
It is available in the trainer with:

```text
--count-prior-impl packed
--count-prior-precompute numpy
--count-prior-storage mmap
```

Correctness checks:

```text
python -m unittest tests.test_count_gate_packed
```

The test compares packed vs Python count-model features/distributions and also
compares the vectorized compiler's rows against the existing per-position
implementation.

Timing checks:

```text
20k direct row benchmark:
  Python per-row loop:       3.800s
  NumPy feature + row path:  0.094s
  max log-prob delta:        ~1.9e-6

50k trainer precompute smoke:
  Python precompute: 9.78s, PPL 9.240, peak RSS 794.6 MB
  NumPy precompute:  0.78s, PPL 9.240, peak RSS 747.9 MB
```

This is the first version where the depth-by-depth idea is clearly paying off.
Next scaling check should be Gutenberg eval-only with
`--count-prior-precompute numpy`, reusing the fitted theta JSON.

Full Gutenberg scaling check:

```text
command shape:
  --count-prior-impl packed
  --count-prior-theta-json runs/gutenberg_count_gate_d8_entropy_suffix.json
  --count-prior-precompute numpy
  --count-prior-storage mmap
  --count-prior-log-prob-dtype float16

build/precompute: 76.92s
initial heldout PPL: 3.57155
runtime including eval: 164.33s
peak RSS: 8216.5 MB
```

This is a large wall-time improvement over the previous full Gutenberg prior
paths:

```text
python count + python precompute:       573.73s, peak 7666 MB
packed + fused python keep-cache:       675.99s, peak 9038 MB
packed + theta-json fused python path:  882.26s, peak 8824 MB
packed + theta-json NumPy path:          76.92s, peak 8216 MB
```

The remaining weakness is memory. The NumPy compiler currently stores all
depth feature arrays plus dense previous-depth Witten-Bell matrices while
building row tables. The next optimization should stream feature/gate arrays
per depth to mmap, then generate rows depth-by-depth without retaining every
depth's feature matrix in resident memory.

Follow-up: moved prefix/suffix feature and gate arrays to a temporary mmap
depth-cache during NumPy precompute.

```text
50k smoke:
  before depth-cache: 0.78s precompute, peak RSS 747.9 MB
  after depth-cache:  1.15s precompute, peak RSS 728.4 MB

Gutenberg 5M eval-only:
  before depth-cache: 76.92s precompute, peak RSS 8216.5 MB
  after depth-cache:  64.91s precompute, peak RSS 8586.0 MB
```

The full-corpus result did not reduce peak memory. It actually increased
`ru_maxrss` slightly while improving precompute time. This suggests the peak is
not primarily retained feature/gate arrays. The likely memory owners are now:

```text
1. packed prefix + suffix count tables for every depth
2. large sorted temporary arrays during table construction
3. dense previous-depth Witten-Bell matrices
```

Next memory work should attack those directly: stream/build one depth group at
a time, or move Witten-Bell state to a lower-precision/chunked representation.

## 2026-06-14 - Prior Strength Ablation

Added:

```text
--prior-strength
```

The frozen count prior is no longer hard-coded as the whole base decision:

```text
final_logits = prior_strength * prior_log_probs + residual_logits
```

This tests whether the prior was starving the neural residual. The answer is
yes, but the setting is sensitive.

Aggressive run:

```text
prior_strength: 0.5
residual_scale: 1.0
residual_L2: 0.02
```

Result:

```text
epoch 0 PPL: 6.70942
epoch 1 PPL: 5.93013
epoch 2 PPL: inf
```

The residual became much more active and attention became selective:

```text
epoch 1 mean_attn_entropy: 2.086
epoch 1 mean_attn_top_weight: 0.333
```

But the run destabilized on the resumed second epoch. This setting removes too
much prior authority and gives the residual too much authority too quickly.

Milder run:

```text
prior_strength: 0.75
residual_scale: 0.25
residual_L2: 0.05
```

Result:

```text
epoch 0 PPL: 5.52120
epoch 1 PPL: 5.41850
```

This is the first clearly positive residual result on the 200k Gutenberg
diagnostic. It also makes attention strongly selective:

```text
mean_attn_entropy: 1.178
mean_attn_top_weight: 0.649
mean_attn_char_distance: 45.3
mean_residual_alpha: 0.278
```

Interpretation: the prior was indeed starving the memory branch. Full prior
authority kept attention nearly uniform. Moderate prior softening both improves
the count-prior floor and gives the residual enough gradient to learn selective
retrieval. The next question is stability over more epochs and whether this
transfers from the 200k diagnostic to the full Gutenberg prior.
