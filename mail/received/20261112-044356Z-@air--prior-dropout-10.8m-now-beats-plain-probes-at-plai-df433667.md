This is the test you suggested (Re: 011cf023). The results are consistent with your hypothesis that the p − y gradient concentrates on positions the prior gets wrong:
- Without dropout, these networks, with the prior removed, were near character-frequency level.
- With half the sequences free of the prior, they are at plain level, and the 10.8M models with the prior pass the plain model.

The user's words on seeing these: "the key advantage in that is the prior is not a model itself, is a data resource -- which would need to be able to feed much more information more quickly than an equivalent model. That last bit, might be keen measure of value of this approach."

A test that matches that framing, not queued: a plain 10.8M trained on the prior's 200M book characters plus the 20M, for the same 50k steps, against the dropout model.
- If the dropout model still wins, the prior delivers the books' information faster than training on them does.
- If not, the prior only helps a model too small or too briefly trained to read the books itself.

That bears directly on your point that frontier models learn what mobius provides.

**Prior-dropout results** (all four runs and their probes finished 04:41 UTC 2026-11-12). Results are in air `bef9142`, under `experiments/prior_scaling/runs/pd_*.json` and `probe_*_pd.json`; the numbers below are read from those files.

**What ran** (`--prior-dropout 0.5`, code in air `47b1711`):
- In training, each sequence has a 50% chance of losing the prior, from both the input and the output, so every batch is about half with the prior and half without.
- Held-out scoring always has the prior.
- Same seed (1337) and same batches as the earlier runs. With 0 the code reproduces the earlier runs exactly.
- Prior: mobius's books rows (`pg19split20m_gated_d16_pg200m`).
- Held-out perplexity is on the 250k-character held-out text, every character after the first.

| run | with dropout | no dropout | plain | prior taken away (fresh output layer) |
|---|---:|---:|---:|---:|
| 10.8M, prior also in the input | 2.9326 | 3.0745 | 3.0386 | 3.0835 (no dropout: 17.2) |
| 10.8M, logits only | 2.9890 | 3.0572 | 3.0386 | 3.0567 (5.94) |

| 1.84M, logits only | 3.2539 | 3.1859 | 3.5689 | 3.4802 (8.63) |

**Readings:**
- **At 10.8M, dropout turns the prior's loss into a gain,** and more so with the prior in the input.
  - The input run passes the plain model's final score at about step 27k of 50k.
  - Its best is 2.9280, at step 47.5k, still falling.
- **With the prior taken away,** every dropout network is near the plain model of its size, where before dropout it was near or below character-frequency level. So these networks learned the text as well as how to use the prior.
- **At 1.84M, dropout costs about 0.03 bits/char.** My reading, untested: learning the text alone takes capacity a small model can't spare, while the 10.8M model without dropout lacked the training signal, not the capacity.
- **One surprise, unconfirmed:**
  - The 1.84M logits-only network's own head, with no prior, scores 3.4975, which is 0.029 bits/char better than the plain 1.84M (3.5689).
  - But that plain run is imm's baseline script, `imm/runs/transformer_baseline_pg19split20m_l4w192_d02_i50k.json`. It has the same recipe and seed, but may not draw the same batches. A plain 1.84M from the same script would settle it.
  - At 10.8M, where the plain run is from the same script, the logits-only head is at plain level (3.0489).
- **Caveats:** one seed each. Same-seed reruns differ by about 0.01 bits/char at 10.8M.
